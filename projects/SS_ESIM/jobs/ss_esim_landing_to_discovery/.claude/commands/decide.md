ดู `$ARGUMENTS` ก่อน: ขึ้นต้นด้วย `Q<เลข>` หรือมีคำว่า "เปลี่ยน" + `Q<เลข>` = **ทาง B เปลี่ยนคำตอบเดิม** · นอกนั้น = **ทาง A เปิดคำถามใหม่**

## ทาง A — เปิดคำถามใหม่

1. ค้นก่อนว่ามีคนตอบเรื่องนี้แล้วหรือยัง (`status/OPEN_DECISIONS.md` · `config/config.json` · `/wiki <คำ>`) — มีแล้ว = บอกว่า "ตอบแล้วใน Q<n> (<ตัวเลือก>) เมื่อ <วันที่>" แล้วหยุด (ห้ามถามซ้ำ)
2. หาเลข Q ถัดไป แล้วเขียน `### Q<n>. <หัวข้อ>` ใต้หัวข้อ phase ที่เหมาะ:
   - **ข้อเท็จจริง** (อ้างไฟล์ / ผล Run Pack / บรรทัด SQL) แยกจาก **สิ่งที่ยังไม่รู้**
   - ตัวเลือกอย่างน้อย 2 ข้อ รูปแบบ `- [ ] A) …` พร้อมผลกระทบ · **[แนะนำ]** 1 ข้อพร้อมเหตุผล + `อ้างอิง: L# / LT#` หรือ `อ้างอิง: ไม่มีบทเรียนที่เกี่ยวข้อง`
   - ข้อมูลที่ต้องใช้ตัดสินใจ และวิธีหามา (ถามใคร / สคริปต์ไหน)
3. **ห้ามติ๊กคำตอบเอง** · เพิ่มรายการใน `status/MIGRATION_STATUS.md` §5 (อ้าง Q<n>) · เชิงออกแบบ → เสนอ `/adr` คู่กัน
4. ถามในแชททันที ทีละข้อ ตัวเลือกเป็นเลข: `1 = A) …` `2 = B) …` … `<สุดท้าย> = ยังไม่ทราบ` พร้อม [แนะนำ] และผลของแต่ละทางแบบภาษาง่าย
5. รับคำตอบตามกติกา "รับคำตอบจากคน" ใน `kit/CLAUDE.kit.md`:
   - ยังไม่ทราบ → เขียนใต้ Q `ยังไม่ทราบ — ต้องหาจาก: <ใคร> · <วันที่>` · Q ยังเปิด
   - ขัดกับไฟล์ → แสดง `คุณตอบ / ไฟล์บอก` แล้วถาม `1 = ยึดไฟล์ [แนะนำ]` `2 = ยึดคำตอบของคุณ` `3 = ยังไม่ทราบ`
   - ตอบยาว → ทวน "เข้าใจว่า … ถูกไหม" ก่อนบันทึก
   - คนในแชทเป็นผู้อนุมัติ (อยู่ใน `shared/approvers.txt`) → ติ๊ก `[x]` + `✅ SA <วันที่> @<login>` แล้วให้ผู้อนุมัติ commit จากบัญชีตัวเอง · ไม่ใช่ → บอกให้ผู้อนุมัติ comment `/approve Q<n> <ตัวเลือก>` ใน PR (ดู `/approve`)

## ทาง B — เปลี่ยนคำตอบเดิม (`/decide Q14` · "เปลี่ยน Q14 เป็น B")

1. อ่าน Q นั้น: คำตอบปัจจุบัน · ใครอนุมัติ · วันที่ — ถ้ายังไม่มีคำตอบ ให้ไปทาง A ข้อ 4
2. ถ้ายังไม่รู้ว่าจะเปลี่ยนเป็นข้อไหน ถามเป็นเลข (ตัวเลือกเดิมทุกข้อ + ยังไม่ทราบ) พร้อม [แนะนำ]
3. **บอกผลกระทบก่อน** (ห้ามแก้ไฟล์ในข้อนี้):
   - ค้นทุกที่ที่อ้าง Q นี้: `grep -rn "Q14" config/ status/ .design/ output/ knowledge/` + ค่าใน `config/config.json` ที่ตั้งจาก Q นี้
   - รัน `python scripts/ws/job_status.py --json` แล้วบอกว่าขั้นไหนต้องทำใหม่ · ไฟล์ไหนต้อง generate ใหม่ · gate ไหนจะกลับเป็น BLOCKED · ถ้า import / go-live ไปแล้วบอกชัด ๆ ว่าต้อง import ทับ (เปิดรอบใหม่ `workspace.py new-round --kind fix`)
   - สรุปเป็นตาราง: ขั้น · ไฟล์ · ต้องทำอะไร
4. ถามยืนยัน: `1 = เปลี่ยน (เก็บประวัติคำตอบเดิม · ต้องอนุมัติใหม่)` / `2 = ไม่เปลี่ยน` / `3 = ยังไม่ทราบ`
5. ตอบ 1 →
   - ใต้ Q เพิ่มบรรทัดประวัติ `ประวัติ: <วันที่> เปลี่ยนจาก <ตัวเลือกเดิม> (✅ เดิม: <ผู้อนุมัติ> <วันที่>) → <ตัวเลือกใหม่> · เหตุผล: <ที่คนบอก> · ขอโดย <ชื่อ>` — **ห้ามลบบรรทัด ✅ เดิม** ให้เปลี่ยน `[x]` ของตัวเลือกเดิมเป็น `[ ]` และคงข้อความ ✅ เดิมไว้ท้ายบรรทัดพร้อม `(ยกเลิก <วันที่>)`
   - ตัวเลือกใหม่ **ยังไม่ติ๊ก** — ต้องให้ผู้อนุมัติอนุมัติใหม่ (`/approve Q14 B` ใน PR หรือทางแชทตามทาง A ข้อ 5) เสมอ แม้ครั้งก่อนเคยอนุมัติแล้ว
   - gate ที่ขึ้นกับ Q นี้: ข้อ manual ที่เคยติ๊กเพราะ Q นี้ → บอกผู้อนุมัติว่าต้องตรวจใหม่ (ไม่แก้ ✅ ของคนอื่นเอง)
   - เพิ่มรายการใน `status/MIGRATION_STATUS.md` §5 · ถ้าเป็นเรื่องออกแบบ เสนอ `/adr` ฉบับใหม่ที่ supersede ฉบับเดิม
6. หลังอนุมัติใหม่ → ทำงานตามตารางผลกระทบทีละขั้น (ขั้นละ 1 ข้อความ) · จบแล้ว `/update-status`
